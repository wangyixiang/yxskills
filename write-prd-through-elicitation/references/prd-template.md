## 写法示例

一条功能需求：

```markdown
| FR-03 | 会员积分累计 | 店主为会员结账时按消费金额累计积分；默认 1 元 = 1 分，店主可修改比例 | Must | US-02 | 给定会员已绑定手机号，当店主录入 38 元消费，则积分增加 38 分，且会员端 5 秒内可见 |
```

一条非功能需求：

```markdown
| NFR-01 | 性能 | 会员列表首屏加载 | 1,000 名会员、4G 网络下 P95 < 2 秒 | 生产环境 APM 采样 |
```

## 成稿检查

- 每个目标都有指标、基线、目标值和时间窗；没有基线的写明“待测”。
- 每条 Must 功能都有可验证的验收标准。
- 每条 NFR 都有数字或明确的验证方式。
- 用户故事与功能需求通过 ID 互相引用。
- “不在本期范围”和“待解决问题”非空，或明确写“无”。
- 所有推断都出现在假设清单中，没有把猜测写成事实。
